# 写作智能体上下文压缩

## 采用的结构

创作空间、技能库、素材库、聊天共用 `pi-runtime-adapter/src/kernel/context`。每段会话独立维护检查点，业务策略决定摘要重点与恢复来源。不会把不同作品、资料库或聊天会话合成一个摘要。

```mermaid
flowchart LR
  A[本轮系统提示和工具权限] --> B[较早对话摘要]
  B --> C[当前可用的技能与正文衔接片段]
  C --> D[保留的原始消息与完整工具调用对]
  D --> E[新的用户要求和本轮作品快照]
```

**恢复内容**是系统按引用重新提供的原始参考内容，不由摘要模型重写：已加载且本轮仍获准读取的技能正文、写正文时的小节结尾、长篇当前章从 Core 读取的保存版本结尾。它帮助恢复写法和衔接细节。恢复片段有独立预算；过大的技能只保留重新加载提示，不截取技能中间的步骤。

摘要保存讨论产生的目标、硬约束、决定、否决方案、进度和下一步。正文、人物、剧情结构、技能和素材文件继续作为内容来源。已提交提案和已确认保存必须分开记录。恢复的正文结尾不能代替修改前的完整读取。

## 与 Pi 的关系

研究基于本地 `/Users/wenjia/project/pi`，主要参考：

- `packages/coding-agent/docs/compaction.md`
- `packages/coding-agent/src/core/compaction/compaction.ts`
- `packages/coding-agent/src/core/session-manager.ts`
- `packages/coding-agent/src/core/agent-session.ts`

沿用 Pi 的上下文估算、近期消息保留、完整轮次优先切分、长单轮分段摘要、旧检查点迭代、超长失败后压缩恢复，以及摘要请求独立路由和缓存隔离。DeepWrite 不直接引入 coding-agent 的文件读写与 JSONL 会话管理，继续使用自己的 Core、提案和会话存储边界。

摘要正文长度由提示词中的软目标引导，目标根据工作预算计算；不会把这个目标当作 API 的 `maxTokens`。生成上限沿用模型配置，由 `pi-ai` 根据本次请求的剩余上下文空间收缩，思考强度也沿用所选模型配置。这样 Gemini 的思考不会因为摘要正文目标较短而提前被截断。输入过长时仍分段摘要，为生成预留窗口空间；摘要不完整或超过检查点保存容量时，保留原上下文。

两条摘要路径共用流进度检测：连续 180 秒没有模型事件时中止，每次请求另有 10 分钟总上限；用户取消会立即生效。`MAX_TOKENS` 截断与超时分别报错，截断的用量记录标记为失败。

## P0：估算与确定性精简

- 汉字与其他非 ASCII 字符按约 1 token、ASCII 按约 0.25 token 估算；可用时结合当前模型最近一次实测用量。模型切换和上下文替换后不继续沿用旧测量。
- 工作预算默认为 160,000 tokens，同时受模型窗口、输出预留和安全余量约束。估算不是模型 tokenizer 的精确计数，供应商拒绝时还有一次压缩恢复。
- 达到工作预算的 50% 后尝试精简；精简后超过 80% 则进入摘要。
- 精简旧的生成快照、已注册且可重读的工具正文、成功提交的旧提案正文和旧思考。用户原话、问答结果、技能内容和未知工具结果不会靠截头截尾来缩短。
- 界面显示估算的压缩前后 token 数，以及压缩后的上下文占用。

## P1：结构化检查点与重启恢复

摘要重点由任务选择：

| 任务 | 重点保留 |
| --- | --- |
| 剧情设计 | 冲突、因果、备选方向、取舍原因、伏笔与回收、否决方案、待定问题 |
| 人物设计 | 动机、关系、人物取舍、尚未写入人物卡的决定 |
| 正文编写 | 小节进度、视角、时态、文风、节奏、字数、退稿原因、续写状态 |
| 剧本 | 剧集进度、场景和台词约定、格式、被否决的情节 |
| 长篇 | 卷、剧情点、章卡和人物引用；跨章进度；连续性记录的读取入口 |
| 技能库 | 方法规则、命名分类、条目处理清单、批量任务进度 |
| 素材库 | 素材引用、来源线索、命名分类、整理进度 |
| 子智能体编写 | 职责、工具和技能选择、提示词修改意见 |
| 普通与项目聊天 | 问题主线、结论、偏好、背景、未解决事项 |
| 角色扮演 | 人设与语气、设定、关系和剧情进展、互动停点 |

检查点通过 `agent.context_compaction` 事件进入会话记录，经现有 Core 会话存储保存。包含摘要、引用、保留起点的 run ID / 时间和压缩前用量。保留原始可见对话，修改历史消息时只使用修改点之前的检查点。

重建模型上下文时发送检查点和它未覆盖的完整消息。不会再按每条 20,000 字或最近 80 条静默截断。传输防护上限为 2,000 条、单条 1,000,000 字符、总计 4,000,000 字符；超过上限会明确停止发送并保留历史。无法定位旧检查点边界时保留全部可见历史，优先避免漏掉约束。

**手动入口的行为：**在写作或聊天输入区安排压缩，并可写明重点；压缩在下一次发送前执行，可以取消安排。设置页提供自动压缩开关、工作预算和独立摘要模型。自动压缩关闭后，手动安排仍可执行。

## P2：持续运行、恢复和兼容

- 一个长任务中，在工具轮次之间检查预算；切分不会让工具结果脱离调用。当前用户要求始终保留。
- 回复完成后、完成事件写入前，若仍超过摘要阈值，整理历史以便下一轮继续。这个阶段属于本次运行，可中止，不创建后台定时任务。
- 供应商报告上下文超长时，删除失败响应、压缩一次、从已有工具结果继续；不重放已经执行的工具副作用。恢复失败会保留原错误。
- 摘要用较小窗口模型时，将完整输入分段迭代；不通过截取用户长消息中间来凑预算。摘要请求有超时、有限重试和中止处理，不完整输出不替换检查点。
- 摘要成功后才提交新消息和状态；失败保留原上下文。固定的当前任务本身仍超出模型容量时，提示缩小范围或换模型。
- 普通子智能体按自己的模型窗口检查继承的上下文；资料库管理子智能体使用自己目标库的策略。各自压缩时清除各自的完整读取凭证，避免凭已移出的正文授权覆盖。纯净·无工具的子智能体不带作品上下文，压缩后也不补回技能或长篇正文结尾。
- 技能恢复每轮按最新授权和附加快照重建；长篇正文结尾通过既有 Main 授权的 Core 只读桥读取，校验作品、文档、版本和 Unicode 分页位置。读取失败则要求重新读取，不虚构结尾。
- 摘要请求的用量归属实际摘要模型，沿用既有用量事件与计费快照。

## 对“更多功能”的影响

| 功能 | 处理方式 |
| --- | --- |
| 聊天 / 项目聊天 / 角色扮演 | 经 `extrasAgent.run` 使用同一内核，各自会话与角色隔离 |
| 修改分析 / 拆书 / 文风比对 | 保留一次性任务的完整输入和既有预算校验，不自动摘要分析证据 |
| 同步 / 备份 / 文本编辑 | 沿用原有机制；压缩只影响模型请求上下文 |
| 提案审批 / 自动保存 | 仍由原有审批和 Core 版本检查处理；摘要不授予写入权限 |

## 验证范围

专项测试覆盖用户原话、问答与未知工具结果保留，完整工具对切分，长输入分段，摘要失败回滚、取消、不完整输出，超长恢复一次，技能权限与预算，长篇当前章结尾，连续精简后的检查点保留，旧历史边界，以及新运行时恢复。

桌面冒烟覆盖 Preload → Main → Agent 事件、写作和聊天压缩，以及 Core 保存检查点后用新会话恢复；会话存储冒烟另覆盖分页读写、崩溃恢复和幂等重试。图片不能被文本摘要替代，因此运行中的旧图片请求继续保留并计入预算。现有会话存储只保存附件名称等元数据；重启恢复会明确告知原始附件未恢复，需要时重新上传。Faux / Mock 验证协议和状态，不代表已经验证真实模型的长期摘要质量；真实写作中的语义遗漏仍应通过已保存原对话和作品来源核对。
